§21.1任务定义与评测

输出是一组 (类别, 置信度, 框)，框常用 (x, y, w, h) 或 (x1, y1, x2, y2)。预测与真值用 IoU 匹配，超过阈值算真正例；按置信度排序得到 PR 曲线，其面积即 AP，多类平均即 mAP。NMS 删除与高分框重叠超过阈值的冗余框——它就是第 10 章非极大抑制思想在框层面的复用。

检测与分类最大的差别是极度类别不平衡：一张图里可能有上万个候选位置，真正包含目标的只有几个。这直接催生了 Focal Loss 与两阶段方法的采样策略。

§21.2三种范式

范式代表核心思路取舍
两阶段R-CNN → Fast → Faster R-CNN → Mask R-CNN先生成候选区域（RPN），再对每个区域分类与回归精度高、小目标好；速度较慢
单阶段YOLO 系列、SSD、RetinaNet在特征图每个位置直接预测框与类别快、适合实时；早期精度落后，已被逐步追平
集合预测DETR 及其变体Transformer + 匈牙利匹配，端到端出固定数量预测去掉 anchor 与 NMS；收敛慢、小目标需额外设计

Anchor-free（FCOS、YOLOX 等）直接预测点到框四边的距离，省去 anchor 尺寸聚类这组超参；Focal Loss 降低易分负样本的权重，让训练聚焦困难样本。

§21.3工程选择与开放词表

  • 实时/边缘：YOLO 系列 + 量化 + TensorRT，优先看 FPS 与功耗。
  • 高精度/研究：MMDetection 或 Detectron2，配置文件化便于消融。
  • 类别会变：GroundingDINO 等开放词表检测用文本提示指定类别，避免每加一类就重训。

不要忘记标注一致性：框该不该包含遮挡部分、截断目标怎么标，直接决定 mAP 的天花板。第 19 章的官方评测脚本必须用上。

pip install ultralytics
yolo predict model=yolov8n.pt source=bus.jpg   # 一行命令跑通官方预训练检测

§常见误区

  • 用自己写的 mAP 报结果：与 COCO API 的边界处理不一致，无法横向比较。
  • NMS 阈值一刀切：人群等密集场景会误删正确框。
  • 忽略小目标：整体 mAP 不错但关键类别几乎检不出。
  • 把开放词表模型当固定类别检测器评测：提示词变化会显著影响结果。
