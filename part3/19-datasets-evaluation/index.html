标注质量往往比模型选择更影响结果。标注规范（遮挡怎么标、边界容差、模糊样本是否丢弃）必须写进文档，否则不同人标出的同一类不可比。

§19.2划分与数据泄漏

  • 随机划分的陷阱：同一视频的相邻帧、同一患者的连续切片、同一产品的多角度照片若被分到训练与测试，指标会虚高。
  • 预处理泄漏：在全量数据上算均值/方差、做 k-means 码本或特征选择，等于让测试集信息进入训练。
  • 调参泄漏：反复用测试集选超参，测试集就变成了验证集。

正确做法是按实体分组划分（group split），并把所有统计量只在训练集上拟合。这一点与第 16 章的传统基线同样适用。

任务主指标辅助 / 陷阱

IoU = 交/并，是检测与分割的共同底座；mAP 是不同召回下 precision 的积分近似，由 PR 曲线下面积给出。工程上务必用官方评测脚本（COCO API / TorchMetrics），自己写的实现常在边界条件上不一致。

§19.4消融与可复现清单

  1. 固定随机种子、依赖版本、硬件与数据划分文件；
  2. 只改一个因素，重复多次取均值与标准差；
  3. 报告参数量、训练时长、推理时延，而不只报精度；
  4. 公开失败案例与负结果；
  5. 提供一条能从头跑通的命令。

本书上卷所有 .m 脚本固定随机种子、参数集中在开头、末尾打印可核对数值，就是同一套可复现约定的最简实现。

§常见误区

  • 用像素准确率评价前景只占 1% 的分割：全预测背景就有 99%。
  • 在全量数据上计算归一化均值：典型且隐蔽的数据泄漏。
  • 跨论文直接比较 FID 数值：采样数量与特征提取网络可能不同。
  • 自己实现 mAP：NMS 与边界条件的细微差异会让结果无法对照。

§习题与思考

  1. 写出 IoU 与 Dice 的关系式，并说明为什么二者单调一致但数值不同。
  2. 为“视频帧级缺陷检测”设计不会泄漏的划分方案，并说明随机划分会高估多少（定性）。
