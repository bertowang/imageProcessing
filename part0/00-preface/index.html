§0.1两条路线的分工

图像处理要回答同一个问题：给定像素矩阵，如何得到想要的语义或数值？两条路线的差别不在“谁更准”，而在知识从哪里来。

维度上卷 · 传统算法下卷 · AI 算法
知识来源人写的先验：线性系统、噪声模型、几何约束、统计分布数据中的统计规律：由损失函数与优化器从标注中拟合
参数少量、有物理含义（核宽、阈值、迭代次数）百万到十亿级、无直接物理含义的权重
可解释性每一步都能写出公式，误差可逐项归因需借助热力图、消融实验与探针间接解释
数据需求一张图就能做，适合小样本、无标注场景依赖大规模标注与算力，分布外容易失效
典型失败模型假设被破坏（噪声非高斯、光照突变、纹理复杂）训练/部署分布不一致、标注偏差、对抗样本
本书输出物可运行的 .m 脚本 + 预期数值原理主线 + 官方开源工程链接

两者不是替代关系：下卷的数据增强、预处理、后处理、评价指标、退化建模，几乎全部来自上卷；很多工业系统仍是“传统流水线做确定性部分 + 网络做不确定部分”。第 26 章会要求同一任务同时做两条基线并对比。

§0.2本书结构与学习闭环

全书 27 章 + 附录，按上下两卷组织：

  1. 卷首（00～02）：约定语言。Octave 环境、图像即矩阵、卷积与评价指标。没有这三层约定，后面的公式和代码都会读错。
  2. 上卷（03～15）：从像素级变换到结构级理解，顺序是增强 → 频域 → 复原 → 几何 → 彩色 → 形态学 → 边缘 → 特征 → 分割 → 描述 → 压缩，最后用一个完整流水线收口。每章至少一个 Octave 实例。
  3. 下卷（16～26）：先用特征工程与机器学习过渡，再进入 CNN、数据集与评测、分类、检测、分割、复原、生成、基础模型，最后是部署与综合项目。每章给官方开源工程链接。

学习闭环固定为四步：读公式 → 跑代码 → 改参数 → 写结论。只跑通不改参数，等于只抄了答案；建议每章记录“手算预期值 → 脚本输出值 → 偏差 → 原因”四列。

§0.3给程序员的阅读约定

本书默认读者写过代码、但未必学过信号与系统，因此所有约定都显式写出来：

代码契约（上卷每章适用）
  • 零依赖：只用 Octave 核心函数（conv2/fft2/interp2/imagesc 等），不调用 image 包的 imfilter/edge/imresize。算法主体全部展开，方便对照公式。
  • 自包含：用 meshgrid 合成测试图，不读外部文件，复制整段代码到 Octave 即可运行。
  • 参数集中：脚本开头的 % ---- 参数区 ---- 集中所有可调量，先改这里。
  • 数值断言：结尾 printf 打印可手算核对的量；页面「预期与判读」给出数值与解释。
  • 可批量验证：设环境变量 IP_HEADLESS=1 即不弹窗；用 tools/run_octave.sh 可跑完全部 .m。

HTML 里的代码块与仓库 code/*.m 由 tools/extract_code.py 自动同步，永远一致；改动请改 tools/chapters_*.py，再运行 python3 tools/build_book.py --force 重新生成。

符号约定：图像记作 f(r,c)，r 是行（向下为增，相当于 y），c 是列（向右为增，相当于 x）；灰度统一归一化到 [0,1] 的 double；卷积核尺寸为奇数；* 在公式里表示卷积、在代码里表示矩阵乘，代码里的卷积一律用 conv2 显式写出。

最容易踩的坑：行列与 xy 顺序相反。f(r,c) 对应坐标 (x,y)=(c,r)。写几何变换时先固定这一点，第 07 章会专门处理。

§Octave 实例

最小可运行脚本：矩阵即图像

%% 00-hello-image.m | 第一个图像程序：矩阵即图像
%% GNU Octave，零第三方依赖；合成图像，无需任何外部文件
clear; close all; clc;
SHOW = ~strcmp(getenv("IP_HEADLESS"), "1");
% ---- 参数区 ----
N = 8;
% ---- 造图：左半 1（白），右半 0（黑）----
[X, Y] = meshgrid(1:N, 1:N);
img = double(X <= 4);
% ---- 数值验证 ----
printf("尺寸: %d x %d (行 x 列)\n", rows(img), columns(img));
printf("min=%.2f max=%.2f mean=%.4f\n", min(img(:)), max(img(:)), mean(img(:)));
printf("第 1 行: "); printf("%.0f ", img(1, :)); printf("\n");
printf("第 1 列之和（应等于行数）: %.0f\n", sum(img(:, 1)));
% ---- 可视化 ----
if SHOW
  figure("name", "00 矩阵即图像");
  imagesc(img, [0 1]); colormap gray; axis image off;
  title("8x8 二值图像：f(r,c)"); colorbar;
end

操作：在 Octave 中直接运行 <code>code/00-hello-image.m</code>；批量验证用 <code>IP_HEADLESS=1 tools/run_octave.sh</code>。　预期与判读：尺寸 8×8；min=0、max=1、均值 0.5；第 1 行是 1 1 1 1 0 0 0 0；第 1 列之和为 8。　文件位置：part0/00-preface/code/00-hello-image.m

代码块右上角可一键复制；本仓库 code/*.m 由 tools/extract_code.py 从这些代码块自动抽取，页面与脚本永远一致。脚本只用 Octave 核心函数，设 IP_HEADLESS=1 可跳过绘图。

§常见误区

  • 把图像当成 x 优先的坐标：矩阵索引是 (行, 列)，即 (y, x)。
  • 只跑代码不改参数：看不出核宽、阈值对结果的影响，等于没做实验。
  • 以为下卷不需要上卷：数据增强、退化建模、评测指标全都是传统算法的直接应用。
